## Why I chose it this way
- sod-enect v1 instead of the newer v2: v2 is v1 with rotate/shear/noise augmentation baked in (24k images). Augmentation belongs in the training loop, not in the stored dataset, otherwise augmented copies leak into val/test.
- Left sod-enect's single `stairs` class unmapped because my targets separate stairs_up / stairs_down and I cannot tell which one each box is.

## What broke and how I fixed it
- fukao only exists as an augmented version (2 copies of every train image). Added `--augmented fukao` to `merge_datasets.py`: keep one copy per Roboflow source stem before re-splitting. Made it opt-in after discovering vip reuses generic names (`7_jpg` × 38 different photos) — a global dedupe silently halved my crosswalk labels.
- First baseline run scored the wrong labels: the per-class rows showed "airplane 106" and "train 175" which were really my motorbike and bus counts. Ultralytics `resolve()`s the image directory, so my symlinked `images/test` led it to `merged/labels` (my 15 ids) instead of `baseline/labels` (COCO ids). Fixed by symlinking each image file rather than the directory, with a test.

## What I learned (in my own words)
- Always sanity-check a metrics table against known instance counts; the wrong-label run "worked" and printed plausible numbers.
- Data leakage can happen before training even starts — at dataset assembly.

- **Narration bundle** (six changes, all above Task 7's spec): far objects are now only spoken in the middle third; `SCORE_THRESHOLD` 0.35 → 0.5; per-class distance (a `CLASS_SIZE` table of real-world heights relative to a person scales the far/near thresholds, so a curb counts as close at box height 0.05 while a person needs 0.5); EMA smoothing of box height (alpha 0.4) so one noisy frame cannot move a bucket; **time-to-contact** as a priority-1 event with its own wording ("car approaching fast, ahead"); and a stereo-panned cue tone before every phrase (`cue()` in `speech.ts`, `ZONE_PAN` in `assistant.ts`) so direction arrives in the correct ear before the words. `Phrase` now carries `zone`. 20 narrator tests, 37 total, tsc + eslint clean.
- Decided navigation stays **local** (obstacle negotiation), not **global** (turn-by-turn). Consumer GPS is ~5 m accurate and 10–20 m between buildings, but "am I on the footpath or in the road" is a 1 m question — the instrument is less precise than the decision. BlindSquare and Microsoft Soundscape reached the same conclusion and announce context instead of directions.

- **Escape direction**: when a priority-1 phrase fires (something ahead-and-close, or a fast approach), the narrator now appends a way out — "pole, ahead, close, go left". A side counts as blocked if anything near or close sits in it; far objects don't stop you stepping across, and crosswalk/door never block because they are things you walk *towards*. Both sides blocked → "stop". Deliberately **no** direction for stairs_up / stairs_down / curb: you cannot side-step a step, and steering someone sideways beside stairs is worse advice than none. 8 new tests, 45 total.
- Three older tests changed expectation rather than breaking: the pole case now correctly says "stop" because the chair on the left and the table on the right genuinely leave nowhere to go.

- **Mic mode setting** after noticing a privacy problem during the phone test: the wake-word listener runs `continuous: true` and restarts forever, and Safari does speech-to-text **in the cloud** — so every conversation happening near the wearer was being uploaded to Apple for as long as the app ran. The wearer consented; bystanders did not. Added `MicMode` ("always" / "hold") to the Assistant with an on-screen toggle. In "hold" the wake-word listener is never started and the mic only opens while the talk button is held. Default stays "always" so the demo is unchanged — the toggle is what shows the trade-off was understood.

- **Two bugs found on the phone, both mine, both now tested.** (1) Pointing at a door said "door, ahead, close, **go left**" — routing the user around the thing they are walking towards. `GUIDES` (door, crosswalk) stopped a side counting as blocked but I never stopped a guide being treated as a blocker *ahead*; `escape()` now returns null for them as well as for level changes. (2) "path clear" fired whenever the blocking object left the frame — including when it left only because the phone turned. An empty frame is not evidence of a clear path. It now requires at least one confirmed track still in view (proof the camera is still seeing the scene) and says "**ahead clear**", not "path clear", because all we ever knew was the middle third of one frame.
- Speech was silent on the phone all evening while the cue tone played and captions showed the right words. Added `speechDiagnostics()` to the status line (`tts started/asked`, voice count, paused flag, last error) rather than keep guessing — `speak()` was swallowing its own `onerror`.
