# 2026-09-13 — Day 3

## What I built today
- Found and downloaded two more Roboflow datasets with the Universe search API: `lamao/sod-enect` v1 (10k street images: bicycle, motorcycle, pole, curb…) and `joydeep-bhattacharya-ghorv/blind-navigation-fukao` v1 (5.2k Indian street images: auto-rickshaw, stairs, door, table…).
- Class mappings for all three datasets (`training/mappings/*.json`) and the merged dataset: 9,035 images (7,228 / 903 / 904), all 15 target classes, smallest class `auto` with 264 training boxes.
- Baseline evaluation of the untouched COCO yolo11n on my test split: `training/results/baseline_test.md`.

## Why I chose it this way
- sod-enect v1 instead of the newer v2: v2 is v1 with rotate/shear/noise augmentation baked in (24k images). Augmentation belongs in the training loop, not in the stored dataset, otherwise augmented copies leak into val/test.
- Left sod-enect's single `stairs` class unmapped because my targets separate stairs_up / stairs_down and I cannot tell which one each box is.

## What broke and how I fixed it
- fukao only exists as an augmented version (2 copies of every train image). Added `--augmented fukao` to `merge_datasets.py`: keep one copy per Roboflow source stem before re-splitting. Made it opt-in after discovering vip reuses generic names (`7_jpg` × 38 different photos) — a global dedupe silently halved my crosswalk labels.
- First baseline run scored the wrong labels: the per-class rows showed "airplane 106" and "train 175" which were really my motorbike and bus counts. Ultralytics `resolve()`s the image directory, so my symlinked `images/test` led it to `merged/labels` (my 15 ids) instead of `baseline/labels` (COCO ids). Fixed by symlinking each image file rather than the directory, with a test.

## What I learned (in my own words)
- Always sanity-check a metrics table against known instance counts; the wrong-label run "worked" and printed plausible numbers.
- Data leakage can happen before training even starts — at dataset assembly.
